# アイコン作成ガイド

公共測量標準図式の記号から、このリポジトリの SVG アイコンを作る手順。

書式の決まりごとは [SVG 設計基準](03_svg_design.md) にある。このガイドは「その基準を満たす SVG を、図式からどう起こすか」を扱う。

---

## 0. 一次資料

| 資料 | 所在 |
|---|---|
| 作業規程の準則 付録7 公共測量標準図式 | https://www.gsi.go.jp/common/000258741.pdf |
| 作業規程の準則（本体） | https://www.gsi.go.jp/gijyutukanri/gijyutukanri41018.html |

以下では上記 PDF をローカルに置いたものを `公共測量標準図式.pdf` と呼ぶ。**159ページ・A4横（841.68 × 595.2 pt）**で、記号の図はラスタ画像ではなくベクターで描かれている。

自治体の拡張 DM コード（`dm-9xxxxxx.svg` のような7桁）は標準図式に載らないので、その自治体の仕様書を見る。

---

## 1. 追加するコードを決める

1. `icons/` に `dm-{コード}.svg` が既にないか確認する
2. 標準図式 PDF 末尾の「数値地形図データ取得分類コード表」でコードと名称を確認する

実データから不足コードを洗い出す場合は、DM を変換した GeoJSON の `Code` を集計して `icons/` と突き合わせる。

### 点アイコンにすべきでないコードがある

図式の「データタイプ」欄を必ず見ること。**線（E2）や面（E1）として定義されている地物は、点アイコンを作っても正しい表現にならない。**

実例: 61-10「被覆」は図式上「線 E2、上縁を4号線・他を2号線で描き、上縁の線には直径0.4mmの半円を2.0mm間隔に付す」と定義されている。静岡市データでは点（E5）が2,542件出現するが、同じコードの線が71,271件・面が25,923件あり、点は少数派だった。この種のコードは点アイコン化を見送り、線・面のスタイル側で表現する。

---

## 2. 図式を読み取る

図式の「図式」欄には、記号の形と **mm 寸法**が入っている。隣の「取得方法」欄には挿入位置（座標点が記号のどこに当たるか）が図示されている。

### 2-1. 対象行の位置を特定する

名称列（`xMin ≈ 122`）の語の `yMin` が、その行の基準になる。

```bash
pdftotext -bbox-layout -f 113 -l 113 公共測量標準図式.pdf p113.xml
```

```python
import re
s = open('p113.xml', encoding='utf-8').read()
for m in re.finditer(r'<word xMin="([\d.]+)" yMin="([\d.]+)" [^>]*>([^<]*)</word>', s):
    if 118 < float(m.group(1)) < 175 and float(m.group(2)) > 60:
        print(f'y={float(m.group(2)):7.1f}  {m.group(3)}')
```

### 2-2. 図式欄を切り出す

図式欄は全ページ共通で **x ≈ 248〜350 pt**。行の基準 y から上下に幅を取って切り出す。ピクセル座標は `pt × dpi / 72`。

```bash
# 例: 600dpi で、名称の yMin=340.2 の行の図式欄を切り出す
#   x0 = 248 * 600/72 = 2066,  W = 102 * 600/72 = 850
#   y0 = (340.2-48) * 600/72 = 2435,  H = 105 * 600/72 = 875
pdftocairo -png -r 600 -f 113 -l 113 -x 2066 -y 2435 -W 850 -H 875 公共測量標準図式.pdf zu
```

寸法の数字が小さくて読めないときは dpi を上げて対象部分だけ再度切り出す。1200〜1800dpi まで上げても図はベクターなので破綻しない。

### 2-3. 変種の扱い

1つのコードに地図情報レベル別（500/1000/2500/5000）や「真形／極小」など複数の図式が載る。形が同じで寸法だけ違うことが多く、その場合はどちらを見てもよい。**形が違う場合は簡略な方（5000用・極小）を採る** — 小サイズで読めることを優先する。

---

## 3. 大きさを決める

mm 寸法をそのまま px に換算すると既存アイコンと揃わない。既存アイコンは形状こそ図式に忠実だが、**大きさは mm 比の厳密再現ではなく、64px キャンバス上で見た目が揃うように描かれている**。

新規アイコンも同じ方針でよい。**形状の縦横比は図式どおりに保ち、絶対サイズは同系統の既存アイコンに合わせる。**

実測値（`tools/inspect_icons.py` で測れる）:

| 系統 | 例 | bbox |
|---|---|---|
| 官公署の円 | 3525 / 3526 / 3536 | 22.0 × 22.0 |
| 〒などの円 | 3509 | 24.4 × 24.4 |
| 括弧つき文字 | 7201「(土)」/ 7211「(岩)」 | 約 26 × 15 |
| 植生 | 6332 / 6334 / 6337 | 10〜16px 角 |
| 横長の線状記号 | 4207 / 5228 / 4219 | 幅 13〜19・高 4〜5 |
| 小さい点記号 | 2238 | 6.2 × 6.2 |

共通の目安:

- bbox は **10〜22px**（横長の記号は幅がこれを超えることもある）
- 線幅は **約 1.1px**
- 中心は **(32, 32)**（既存アイコンは全件これに揃っている）

## 4. 塗りパスを組み立てる

設計基準どおり、**ストロークは使わず線も塗りパスで表現する**。手で `d` を書くのは現実的でないので `tools/gen_icons.py` のヘルパを使う。

```bash
python3 tools/gen_icons.py            # tools/out_icons/ に書き出す（確認用）
python3 tools/gen_icons.py --install  # icons/ に直接書き出す
```

| ヘルパ | 用途 |
|---|---|
| `seg(p0, p1)` | 直線1本（バットキャップの矩形になる） |
| `polyline([p0, p1, ...])` | 折れ線。頂点はマイター接合され、突き合わせの欠けが出ない |
| `arc_band(cx, cy, r, a0, a1)` | 円弧。角度はラジアン、Y は下向き |
| `ring(cx, cy, r)` | 穴あきの円。外円と内円を逆回りにして nonzero で抜く |
| `glyph(ch, height, cx, cy)` | 漢字などの字形アウトライン |

戻り値はいずれもパスデータの文字列なので、`+` で連結して `write(コード, データ, 説明)` に渡すと1パスの SVG になる。

作図例はスクリプト末尾にある。図式から読んだ寸法と、そこから決めた px 値をコメントに残しておくと後から検証できる。

```python
# ---- 72-12 露岩 ----
# 図式: 上に開いた半円（幅1.5mm・深さ0.75mm）＋弦の中央に短い線分（0.5mm）。
# 幅14px とすると半径7px、線分長 14*(0.5/1.5)=4.67px。
w = 14.0
r = w / 2
chord_y = CY - r / 2
bar = w * (0.5 / 1.5)
d = (arc_band(CX, chord_y, r, 0, math.pi) +
     seg((CX - bar / 2, chord_y), (CX + bar / 2, chord_y)))
write('7212', d, '半円＋弦中央の線分')
```

### 方向レイヤ（E6）の記号は右（東）向きに描く

方向レイヤの記号は `Angle` 属性で回転して使う。**角度0＝水平右（東）**が基準なので、記号の軸が水平右を向いた状態で作図する。図式の図はたいてい既にその向きで描かれている。

記号レイヤ（E5）は回転しないので、図式の向きのままでよい。

### 字入りの記号

○の中に漢字が入る記号（35-31 保健所など）は、書体のアウトラインを使う。`glyph()` は **Noto Sans JP**（SIL OFL、MIT の本リポジトリと両立する）から字形を取り出し、`transform` 属性を使わずパス座標に焼き込んで1パスにまとめる。

ウェイトは 400 が既存アイコンの線幅（約1.1px）に近い。円の外径 22px に対して字の高さ 12.5px が収まりの目安。

## 5. 検証する

### 図式と見比べる

切り出した図式画像と、作った SVG のレンダリングを並べて確認する。読み取りの手順そのものを検証したいときは、**既にあるアイコンを同じ手順で図式から読み直し、実物と一致するか**を見るとよい（例: 7211 岩がけ = 図式「(岩) 3.5×2.5mm」）。

### 数値で確認する

```bash
python3 tools/inspect_icons.py dm-7212            # 個別
python3 tools/inspect_icons.py dm-7212 dm-3525    # 既存と並べて比較
```

bbox・中心・線幅を実測して出す。中心が (32, 32)、線幅が 1.0〜1.3px、bbox が同系統の既存アイコンと同程度なら、基準を満たしている。

### 小さいサイズで見る

実際の表示は 25〜30px 程度になる。その大きさでレンダリングして、潰れていないか確認する。

## 6. ビルドして公開する

```bash
npm install
npm run build     # _site/ に sprite.png / sprite.json / @2x の4ファイル
npm run start     # ローカルサーバーで確認（http://localhost:8080）
```

`main` に push すると GitHub Actions（`.github/workflows/icons.yml`）がビルドして GitHub Pages にデプロイする。公開後に4ファイルとも 200 が返ること、`sprite.json` に新しいキーが入っていることを確認する。

```bash
curl -s https://<user>.github.io/<repo>/sprite.json | python3 -c \
  "import json,sys; j=json.load(sys.stdin); print(len(j)); print([k for k in j if 'dm-7212' in k])"
```

MapLibre 側は `icon-image` でスプライトのキー（= ファイル名から拡張子を除いたもの）を参照する。複数スプライトを読ませている場合は `<スプライトid>:dm-7212` の形になる。
